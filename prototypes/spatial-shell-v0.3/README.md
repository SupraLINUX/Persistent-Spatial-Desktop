# Spatial Shell Prototype v0.3\n\nInteractive web prototype for validating the PSD spatial model and the Spatial Glass v0.1 design system.\n\nThis is **not** the production shell and does not imply compositor/runtime functionality is implemented.\n\n## Goals\n\n- CENTER remains a conventional desktop with wallpaper, desktop icons and ordinary floating windows.\n- LEFT, RIGHT, TOP and DASH are persistent surfaces already present around CENTER.\n- Mouse edge dwell reveals a surface by rigid translation.\n- Nothing scales or compresses during spatial movement.\n- Clicking the visible displaced CENTER returns home without forwarding the click.\n- DASH is the direct lower region; there is no intermediate BOTTOM.\n- Visual treatment uses a continuous spatial background to avoid the hard color seams found in earlier prototypes.\n- CSS fallbacks mirror `spec/design-tokens.json`; when served from the repository root the prototype loads the canonical token file at runtime.\n\n## Run\n\nFrom the repository root:\n\n~~~bash\npython3 -m http.server 8080\n~~~\n\nThen open:\n\n~~~text\nhttp://localhost:8080/prototypes/spatial-shell-v0.3/\n~~~\n\nServing over HTTP is recommended so `app.js` can load `spec/design-tokens.json`.\n\n## Controls\n\nMouse:\n\n- dwell on LEFT / RIGHT / TOP / BOTTOM screen edge for ~180 ms;\n- click visible CENTER to return;\n- Esc returns to CENTER.\n\nPrototype-only keyboard controls:\n\n- Left Arrow -> LEFT\n- Right Arrow -> RIGHT\n- Up Arrow -> TOP\n- Down Arrow -> DASH\n- Esc -> CENTER\n\nThese arrow bindings are only for quick prototype testing and are **not** proposed PSD product shortcuts.\n\n## Known limitations\n\n- Browser prototypes cannot validate real compositor-level window transforms.\n- Four-finger Wayland touchpad gestures cannot be faithfully implemented inside a browser page.\n- Desktop windows/icons are mock content.\n- Blur/shadow appearance varies by browser/GPU.\n\nThe purpose of this prototype is visual/spatial validation before the Qt/QML runtime implementation.\n
